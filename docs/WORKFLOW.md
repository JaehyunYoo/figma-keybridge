# 협업 규칙과 실제 Figma 확인

## 관리 원본

| 데이터 | 원본 | 수정 담당 |
|---|---|---|
| 화면과 텍스트 노드 | Figma | 디자이너/개발자 |
| 텍스트 노드에 연결한 키 | Figma plugin data | 디자이너/개발자 |
| 확정 원문·번역·상태 | Git의 catalog.md | 문구/번역 담당자, PR 리뷰 |
| 앱 번역 JSON | MD에서 생성한 Git 파일 | 생성 도구 |

문구 확정 전에 키를 만들어 개발합니다. 키는 의미에 따라 안정적으로 유지합니다. 문자열이 같다는 이유만으로 재사용하지 않습니다.

## 일반 변경

1. 최신 Git MD를 플러그인으로 가져옵니다.
2. 개발자가 디자인 화면의 키를 연결하고 MD를 내보냅니다.
3. PR에서 새 키와 `pendingSource`를 확인합니다.
4. 원문 변경 제안을 적용하면 원문과 모든 번역이 재검수 상태가 됩니다.
5. 담당자가 각 언어를 검수하고 `approved`로 변경합니다.
6. 필수 언어를 명시하여 check/export를 실행하고 JSON도 같은 PR에 포함합니다.

개발 중에는 `--allow-draft`를 사용합니다. 미해결 변경 제안은 먼저 수락하거나 거절합니다.

## Git 버전

- 평소에는 기능 브랜치에서 코드·MD·JSON을 같이 변경합니다.
- 출시를 준비할 때 필요하면 `release/1.1.1` 같은 브랜치를 사용합니다.
- 실제 출시한 커밋에는 `v1.1.1` 같은 태그를 붙입니다.
- MD 충돌은 generated JSON에서 해결하지 않습니다. MD를 먼저 해결하고 JSON을 다시 생성합니다.

## 첫 실제 파일 확인 (복제한 테스트 파일에서 진행)

- [ ] Figma가 발급한 플러그인 ID로 설치된다.
- [ ] 프레임/텍스트 선택 및 현재 페이지 스캔이 된다.
- [ ] 키 저장 후 플러그인을 닫았다 열어도 키가 남아 있다.
- [ ] 문구를 수정해도 키가 유지된다.
- [ ] MD를 내보내고 다시 가져올 수 있다.
- [ ] 검수된 MD와 다른 문구를 내보내면 pendingSource가 생긴다.
- [ ] 같은 키의 서로 다른 문구가 선택 영역에 있으면 차단된다.
- [ ] 키 연결 저장은 Undo로 되돌릴 수 있다.
- [ ] 다른 팀원이 동일 플러그인 ID로 같은 키를 읽는다.
- [ ] 프레임 복제 시 키 재사용/분리를 팀 규칙대로 확인한다.
- [ ] 출력한 평면 JSON을 실제 Flutter 번역 로더가 읽는다.
- [ ] 원문 수정 후 검수 상태·필수 언어 체크가 출시를 차단한다.

## 다음 결정이 필요한 부분

실제 앱의 JSON 예시를 기준으로 평면/중첩 구조, 변수 및 복수형 규칙을 맞춥니다. 이 프로토타입은 평면 문자열 JSON만 지원합니다. 자동화가 필요하면 현재 앱 저장소의 CI에 check/export와 생성 결과 diff 검사를 붙입니다. 플러그인에 Git 인증을 넣는 대신 저장소에서 처리합니다.
