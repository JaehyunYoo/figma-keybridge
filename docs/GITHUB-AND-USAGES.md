# GitHub 연결과 버전별 키 사용처 (v0.3)

## GitHub 첫 연결

기본 저장소는 `JaehyunYoo/figma-keybridge`, 기본 브랜치는 `main`, 파일 경로는 `localization/catalog.md`입니다. 모두 UI에서 변경할 수 있습니다. GitHub.com REST API를 사용하며 GitHub Enterprise 전용 호스트는 지원하지 않습니다.

1. GitHub에서 fine-grained personal access token을 생성합니다. 선택한 저장소에만 Contents 및 Pull requests 읽기/쓰기 권한을 줍니다. 조직 저장소는 별도 승인이 필요할 수 있습니다.
2. 토큰을 플러그인 **GitHub** 탭에 입력합니다. 토큰을 채팅으로 보내거나 MD/Git에 기록하지 마세요.
3. **카탈로그 가져오기**를 누릅니다. 가져온 카탈로그는 기존 키 제안과 병합의 기준이 됩니다.
4. 저장소가 비어 있다면 **빈 저장소 초기화** 버튼이 나옵니다. 이 버튼은 선택한 기본 브랜치에 빈 카탈로그를 첫 커밋으로 직접 생성합니다. 최초 커밋이 있어야 PR을 만들 수 있습니다. 플러그인 설치만으로 실행되지는 않습니다.
5. 키 편집 탭에서 Figma 텍스트를 불러와 연결하고 저장합니다.
6. GitHub 탭에서 **PR 변경 내용 확인**을 눌러 키 목록과 제출할 MD를 검토합니다.
7. **초안 PR 만들기**를 누르면 `keybridge/<고유값>` 브랜치에 MD를 커밋하고 draft PR을 생성합니다. 자동 병합·출시는 하지 않습니다.

토큰 입력 후 **이 기기에 저장**을 누르면 Figma `clientStorage`에 토큰·저장소·브랜치·파일 경로를 보관하고 다음 실행 때 자동으로 불러옵니다. 저장하지 않으면 현재 창에서만 사용합니다. **연결 해제**는 현재 입력값을 비우고 저장된 연결 정보도 삭제합니다. 새 토큰으로 교체하거나 저장소 설정을 바꿨다면 다시 저장하세요.

로컬 저장소는 Figma 문서나 Git으로 공유되지 않지만 암호화된 비밀 보관함은 아닙니다. 개인 기기에서 사용하세요. 같은 플러그인 ID를 유지한 UI/코드 업데이트는 저장 데이터를 유지합니다. 플러그인 ID 변경, 기기·클라이언트 변경, 캐시 삭제, 토큰 만료·철회 시에는 다시 설정해야 합니다. 현재 설치 manifest ID는 유지합니다.

레포/브랜치/경로를 수정하면 이전 연결·검토 상태가 무효화됩니다. 토큰 생성은 GitHub에서 직접 수행합니다.

### 충돌 및 실패

- MD는 기본 브랜치의 특정 커밋에 고정해서 읽습니다.
- 제출 시 기준 브랜치가 이미 변경됐다면 중단하고 다시 가져오도록 안내합니다.
- 기본 브랜치를 덮어쓰지 않고 별도 브랜치에 커밋합니다. 최초 빈 저장소 초기화만 예외입니다.
- 다른 MD를 잘못 연결해 GitHub의 기존 키·검수 원문·번역·화면 기록을 지우려 하면 차단합니다.
- 브랜치 생성 뒤 커밋/PR 요청에 실패하면 브랜치 이름을 안내합니다. 먼저 GitHub에서 상태를 확인하세요. 자동 재시도나 브랜치 삭제는 하지 않습니다.
- 원본 파일은 1MB 이하 MD만 지원합니다.
- 기존 MD를 canonical 형식으로 다시 쓰므로 블록 밖 자유 설명은 기본 안내문으로 교체될 수 있습니다. 제출 MD 전체를 확인하세요.

현재 실제 계정의 토큰으로 커밋/PR을 생성하는 통합 시험은 수행하지 않았습니다. 테스트는 모의 GitHub API로 실행했습니다.

## 키 사용처

### 무엇을 표시하나

- **최초 등록 버전**: 새 키를 추출할 때 입력한 기록 버전. 기존 키는 유지합니다.
- **카탈로그에 기록된 화면**: 버전, Figma 문서·노드, 페이지·프레임. 내보낸 기록이 누적됩니다.
- **현재 파일에서 확인**: 현재 파일 전체를 실제 조회해서 발견한 키 연결. 다른 페이지도 포함합니다.
- **여러 위치에 연결된 키만**: 문서·노드의 고유 위치가 2곳 이상인 키를 필터링합니다. 한 노드가 여러 버전에 기록된 것만으로 공통 키가 되지는 않습니다.

### 사용 예

1. `1.1.0` 작업에서 기록 버전을 `1.1.0`으로 입력합니다.
2. 저장 버튼에 `common.save`를 연결하고 MD/GitHub에 반영합니다.
3. `1.1.1` 작업을 시작할 때 최신 카탈로그를 가져옵니다.
4. 다른 화면의 저장 버튼에서 키 입력창의 기존 키 후보 `common.save`를 선택합니다.
5. 기록 버전을 `1.1.1`로 입력하고 저장·내보내기 합니다.
6. 키 사용처에서 `common.save`를 선택하면 최초 버전은 `1.1.0`을 유지하고, 두 버전의 화면 기록을 확인할 수 있습니다.

**현재 파일 전체 조회** 결과 중 카탈로그에 있는 키의 사용처는 다음 MD/PR에 함께 기록합니다. 조회만으로 GitHub에 쓰거나 노드의 키를 바꾸지는 않습니다.

### 범위와 주의점

- 기록 버전은 팀이 입력하는 앱 버전 이름입니다. Git branch/tag 이름에서 자동 추론하지 않습니다.
- 과거 MD에 버전 정보가 없다면 `기록 없음`으로 표시합니다. 이전 Git 커밋을 자동 조사해 과거 이력을 복원하지 않습니다.
- 과거 화면 기록은 삭제되지 않습니다. 현재 사용 여부를 확인하려면 파일 전체 조회 결과를 봅니다.
- **Flutter/Dart 코드의 참조 위치는 아직 포함하지 않습니다.** 이번 버전의 사용처는 Figma의 연결과 카탈로그 기록입니다.
- 여러 Figma 파일의 모든 실시간 상태를 조회하지 않습니다. 다른 파일은 가져온 MD에 기록된 위치만 표시합니다.
- Figma file key가 수집 가능한 경우 외부 Figma 링크를 표시합니다. 현재 파일의 위치 보기는 Plugin API로 해당 페이지를 열고 노드를 선택합니다.
- 토큰 설정 없이도 로컬 MD·키 사용처 기능은 사용 가능합니다.

## 설치된 플러그인 업데이트

바탕화면의 `figma-keybridge/plugin` 폴더에 최신 code.js, ui.html, manifest.json을 반영합니다. 이번 버전은 manifest에 `https://api.github.com` 접근이 추가됩니다. 플러그인을 닫고 다시 실행하세요. 도메인 차단 오류가 나면 동일 manifest.json을 Figma 개발 플러그인으로 다시 가져오세요.

## 앱 JSON 자동 생성

이번 GitHub PR은 MD 카탈로그만 갱신합니다. JSON 변환 CLI는 기존과 동일합니다. 앱 저장소의 CI에서 다음처럼 필수 언어를 명시해 실행할 수 있습니다. 해당 저장소에 scripts/catalog.cjs와 src/catalog.cjs도 함께 배치해야 합니다.

```sh
node scripts/catalog.cjs check localization/catalog.md --locales ko,en
node scripts/catalog.cjs export localization/catalog.md --out assets/translations --locales ko,en
```

참고: [GitHub Git refs API](https://docs.github.com/en/rest/git/refs), [Repository contents API](https://docs.github.com/en/rest/repos/contents), [Pull requests API](https://docs.github.com/en/rest/pulls/pulls).


## 버전별 키 목록 · 문구 비교 (v0.4)

키 사용처 탭 상단의 **버전별 키**에서 조회 버전을 선택하면 그 버전에 기록된 모든 키·문구·사용처가 표로 표시됩니다. 검색과 키 개수 표시를 제공합니다. **두 버전 비교**에서는 기준/비교 버전을 직접 선택해 문구 변경·유지, 사용처 추가·미확인과 양쪽 문구/화면을 확인합니다. 차이가 있는 키만 볼 수도 있습니다.

- 기록 버전을 입력하고 MD 내보내기 또는 GitHub PR을 만들 때 `versionRecords`에 그 시점의 포함된 Figma 텍스트를 저장합니다. MD 내보내기 후에는 현재 창의 목록도 즉시 갱신됩니다. 다음 세션에서는 저장한 MD를 가져오거나 PR 병합 후 GitHub에서 가져오세요.
- 문구 비교는 **추출한 Figma 원문** 기준입니다. 원본 카탈로그의 검수된 source·translations를 덮어쓰지 않습니다. 언어별 번역 값 비교는 이번 기능에 포함하지 않습니다.
- 같은 버전으로 재추출하면 관측한 키의 문구를 최신 값으로 갱신하고 사용처를 누적합니다. 추출하지 않은 키는 보존합니다. Git 커밋 간 모든 변경 이력을 펼쳐 보여주는 기능은 아닙니다.
- 선택한 프레임의 추출 기록이므로 전체 앱 스냅샷으로 취급하지 않습니다. 화면 전체 조회의 위치 기록만 있는 키는 문구가 미기록일 수 있습니다.
- 한쪽 기록에 없다는 이유만으로 신규/삭제를 확정하지 않습니다. `이전 기록에 없음` / `현재 기록에서 미확인`으로 표시합니다.
- 기존 v0.3 카탈로그의 버전별 위치는 그대로 표시하지만 과거 문구는 `문구 기록 없음`으로 표시합니다. 현재 source로 과거 문구를 추정하지 않습니다.
- `examples/version-comparison.md`는 1.1.0과 1.1.1 비교용 데모입니다. 실제 GitHub 카탈로그와 연결하지 않고 로컬 MD 가져오기로 확인하세요.
